## 1. ที่มาและความต้องการ (Background & Problem Statement)

ในระบบแปลเกมแบบทีมเดิม ผู้ใช้งานทั่วไปที่ต้องการช่วยเสนอคำแปลมักติดปัญหา:
1. **กำแพงการลงทะเบียน / ขอสิทธิ์ (Membership Barrier)**: ผู้ใช้ต้องสร้างบัญชี, รอแอดมินกดอนุมัติสิทธิ์ หรือกรอกอีเมลก่อน จึงจะสามารถพิมพ์คำแปลได้ ทำให้เสียโอกาสที่ชุมชนคนเล่นเกมจะเข้ามาช่วยแปลประโยคที่ตนเองคุ้นเคย
2. **ความเสี่ยงต่อความถูกต้องของ Master String**: หากปล่อยให้ทุกคนกดแก้คำแปล Master ทันที คำแปลหลักอาจถูกแทนที่ด้วยคำแปลที่ไม่สมบูรณ์ แท็กหาย หรือมีอักขระ CJK หลุดรอด
3. **ภาระของแอดมินในการตรวจทาน (Review Fatigue)**: เมื่อเปิดให้ชุมชนส่งข้อเสนอเข้ามาจำนวนมาก แอดมินต้องนั่งตรวจทีละประโยคว่าแท็กเกมตรงไหม หลุดภาษาจีน/ญี่ปุ่นไหม ศัพท์ตรงคลังคำศัพท์ (Glossary) หรือไม่

## 2. โซลูชันสถาปัตยกรรม 2 ระดับ (Two-Tier Architecture)

ระบบ TStudio ได้รับการปรับโครงสร้างเป็น **Open Contributor + Moderated Master**:

```
                       ┌─────────────────────────┐
                       │  ผู้ใช้ทั่วไป / สมาชิกชุมชน  │
                       └────────────┬────────────┘
                                    │
                                    ▼  (ไม่ต้องสมัครสมาชิก / เข้าได้ทันที)
                       ┌─────────────────────────┐
                       │  นามปากกานักแปลอิสระ     │
                       │  (Anonymous Local Id)   │
                       └────────────┬────────────┘
                                    │
                                    │  ส่งข้อเสนอคำแปล (Enter ↵)
                                    ▼
                       ┌─────────────────────────┐
                       │  Suggestions Repository │
                       │  (ข้อเสนอคำแปลรอดำเนินการ)│
                       └────────────┬────────────┘
                                    │
                                    ▼
       ┌────────────────────────────────────────────────────────┐
       │   AI Proposal Inspection Engine (aiProposalChecker)   │
       │   - ตรวจสอบ Tag Integrity (TagGuard)                   │
       │   - ตรวจจับ CJK Leaks (cleanCjkLeak)                    │
       │   - ตรวจสอบ Glossary Term Matching                     │
       │   - คำนวณ Quality Score (0 - 100) & Badges              │
       └────────────────────────────┬───────────────────────────┘
                                    │
                                    ▼
                       ┌─────────────────────────┐
                       │ Consensus Review Modal  │
                       │ (เฉพาะ Admin / Modder)  │
                       └────────────┬────────────┘
                                    │
                                    │  1-Click "เลือกเฉพาะ AI ผ่าน 100%"
                                    ▼
                       ┌─────────────────────────┐
                       │     Master Translation  │
                       │     (สำหรับ Build เกม)   │
                       └─────────────────────────┘
```

## 3. รายละเอียดการทำงานของระบบ (Key Components)

### 3.1 ระบบนักแปลอิสระไร้รอยต่อ (Zero-Friction Anonymous Contributor)
- ทุกคนที่เปิดหน้าเว็บ TStudio จะได้รับ Object ผู้ใช้งานชั่วคราวที่มี `anonId` (เช่น `anon_3a1b...`), นามปากกาเริ่มต้น `'นักแปลอิสระ'`, และ Avatar สุ่ม บันทึกลงใน `localStorage`
- สามารถเข้าชมและแปลทุกโปรเจกต์ได้ทันทีผ่านปุ่ม **"เข้าห้องแปล (เสนอคำแปลได้ทันที)"**
- สามารถเปลี่ยนชื่อนามปากกาและเลือก/อัปโหลดรูปโปรไฟล์ได้ตลอดเวลาใน `UserProfileModal` โดยไม่ต้องใช้อีเมล
- ระบบจดจำประวัติโปรเจกต์ที่เปิดค้างไว้ (`tstudio_recent_projects`) และบรรทัดล่าสุดที่แปล (`tstudio_last_string_${projectId}`) ให้เปิดกลับมาทำต่อได้ทันที

### 3.2 การจำแนกสิทธิ์และความปลอดภัย (Access Control & Safety)
- ฟังก์ชัน `canReviewAndApprove(role)` ตรวจสอบว่าผู้ใช้มีบทบาท `lead`, `admin`, `proofreader`, หรือ `modder` หรือไม่
- หากเป็นผู้ใช้ทั่วไป (`contributor` / `anonymous`):
  - การพิมพ์คำแปลแล้วกด Enter จะเป็นการ **"ส่งข้อเสนอคำแปล & บรรทัดถัดไป ↵"**
  - ตัวแปร `effectiveAutoApprove` จะถูกบังคับเป็น `false` เสมอ ทำให้ไม่สามารถเขียนทับคำแปล Master ได้โดยตรง
- หากเป็นแอดมินหรือม็อดเดอร์:
  - สามารถสลับโหมด Auto-Approve เพื่ออนุมัติเป็น Master ทันที หรือกดตรวจสอบผ่านหน้าต่าง Consensus

### 3.3 เครื่องยนต์ AI คัดกรองคำแปล (`aiProposalChecker.ts`)
เมื่อข้อเสนอถูกส่งเข้ามา ระบบ Consensus Modal จะส่งข้อความไปประเมินผ่าน `inspectProposal(source, target, glossary)`:
1. **Tag Integrity**: ตรวจจับแท็กควบคุมเกม เช่น `{0}`, `%s`, `\n`, `[b]`, `<color>`, `<key>`, ฯลฯ หากข้อเสนอคำแปลทำแท็กหายหรือเพิ่มแท็กแปลกปลอม จะติดธงเตือน `⚠️ แท็กหลุดหาย`
2. **CJK Leak Prevention**: กรองอักขระภาษาจีน ญี่ปุ่น เกาหลี ที่อาจติดมาจากการก๊อปปี้ หรือข้อความที่ยังแปลไม่หมด หากตรวจพบจะติดป้ายเตือน `⚠️ มีอักษรจีน/ญี่ปุ่น`
3. **Glossary Matching**: สแกนหาคำศัพท์เฉพาะทางจากคลังคำศัพท์ของโปรเจกต์ หากแปลตรงตามมาตรฐานจะได้รับแต้มพิเศษ
4. **AI Quality Score (0-100)**: ประเมินคะแนนความสมบูรณ์แบบเรียลไทม์ พร้อม Badge แสดงผล:
   - `✅ AI ผ่าน 100%`: แท็กครบ ไร้ CJK ศัพท์ถูกต้อง
   - `⚠️ มีจุดเฝ้าระวัง`: พบจุดผิดสังเกตที่แอดมินต้องตรวจซ้ำก่อนอนุมัติ

### 3.4 Consensus Review Modal (ระบบฉันทามติสำหรับแอดมิน)
- หน้าต่างตรวจสอบคำแปลของแอดมินมีแท็บฟิลเตอร์:
  - **ทั้งหมด**
  - **✅ ผ่าน AI 100%**
  - **⚠️ มีจุดเฝ้าระวัง**
- ปุ่มลัด **"เลือกเฉพาะ AI ผ่าน 100% (N คำแปล)"** ช่วยให้แอดมินสามารถอนุมัติคำแปลของชุมชนที่ผ่านการตรวจทานของ AI เข้าเป็น Master ได้ด้วยคลิกเดียว รวดเร็ว ปลอดภัย และไม่เสียเวลา
